Clase 3 · ABI, llamadas y pilaClass 3 · ABI, calls and stack

rdi rsi rdx · rax · call/ret · rsp · push/pop
Objetivo

Entender el contrato que permite que una función C llame a una función escrita en ensamblador. Al terminar, debes poder explicar cómo llegan los argumentos a una función ASM, dónde se coloca el valor de retorno, qué hace ret, qué registros puedes modificar libremente y por qué la pila debe quedar equilibrada.

1. Qué es la ABI

ABI significa Application Binary Interface. No es una instrucción concreta, sino un acuerdo entre el código llamador y el código llamado.

En Libasm usamos la ABI System V AMD64 sobre Linux x86-64. Esta ABI define, entre otras cosas:

El primer argumento llega en rdi.
El segundo argumento llega en rsi.
El tercer argumento llega en rdx.
El valor de retorno sale en rax.
ret vuelve al llamador usando una dirección guardada en la pila.
Algunos registros se pueden destruir; otros se deben preservar.
La pila debe estar correctamente alineada antes de llamar a otra función.

Sin esta convención, C y ASM no sabrían dónde dejar o buscar argumentos y resultados.

2. Argumentos de función

Los primeros argumentos enteros o punteros llegan en este orden:

1. rdi
2. rsi
3. rdx
4. rcx
5. r8
6. r9

Por ejemplo:

size_t ft_strlen(const char *s);

ft_strlen recibe un solo argumento, así que al entrar en ASM:

rdi = dirección del primer byte de la cadena

Si C llama:

ft_strlen("Hi");

y la cadena está en memoria así:

DirecciónContenido
0x10000x48 'H'
0x10010x69 'i'
0x10020x00 '\0'

entonces al entrar:

rdi   = 0x1000
[rdi] = 0x48

rdi contiene la dirección. [rdi] lee el contenido de esa dirección.

Para dos argumentos:

char *ft_strcpy(char *dst, const char *src);

al entrar:

rdi = dst
rsi = src

Si dst empieza en 0x8000 y src empieza en 0x9000:

rdi = 0x8000
rsi = 0x9000

Leer un byte de src y escribirlo en dst puede hacerse así:

mov al, [rsi]
mov [rdi], al

3. Valor de retorno

La ABI dice que los retornos enteros o punteros salen en:

rax

Si una función ASM termina con:

mov rax, 5
ret

y C hizo:

int x = mi_funcion();

entonces C recibe:

x = 5

En ft_strlen, rax se usa como contador porque al final ese contador es exactamente el valor que debe devolver la función.

En ft_strcpy, el contrato exige devolver el dst original. Por eso conviene guardar ese valor antes de avanzar el puntero:

mov rax, rdi

Luego se puede modificar rdi durante la copia, mientras rax conserva el inicio original de dst.

4. call, ret y dirección de retorno

Cuando C llama a una función, la CPU ejecuta conceptualmente una instrucción call.

call hace dos cosas:

1. Guarda en la pila la dirección a la que hay que volver.
2. Salta a la función llamada.

ret hace lo contrario:

1. Lee de la pila la dirección de retorno.
2. Salta a esa dirección.

Por eso una función ASM normalmente acaba con:

ret

La función no necesita saber manualmente a qué línea de C volver. La dirección de retorno ya fue guardada por call.

5. Registros volátiles y preservados

La ABI separa los registros en dos grupos.

Registros volátiles, también llamados caller-saved:

rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11

Una función puede modificarlos libremente. Si el llamador necesitaba conservarlos, el llamador debía guardarlos antes del call.

Registros preservados, también llamados callee-saved:

rbx, rbp, r12, r13, r14, r15

Si una función modifica uno de estos registros, debe restaurarlo antes de ret.

Incorrecto:

mi_funcion:
    mov rbx, 123
    ret

Correcto si de verdad necesitas usar rbx:

mi_funcion:
    push rbx
    mov rbx, 123
    ; usar rbx...
    pop rbx
    ret

Para las funciones obligatorias simples, muchas veces la mejor decisión es no usar registros preservados.

6. La pila

La pila es una zona de memoria gestionada principalmente mediante rsp, el stack pointer.

En x86-64 la pila crece hacia direcciones menores.

push rax

equivale conceptualmente a:

rsp = rsp - 8
[rsp] = rax

porque un registro de 64 bits ocupa 8 bytes.

pop rax

equivale conceptualmente a:

rax = [rsp]
rsp = rsp + 8

Ejemplo:

rsp = 0x1000
rax = 55

Después de:

push rax

queda:

rsp   = 0xff8
[rsp] = 55

7. Equilibrio de la pila

Cada push debe estar compensado por un pop antes de ret, salvo que estés ajustando la pila explícitamente con sub rsp, ... y add rsp, ....

Esta función tiene un problema grave:

ft_bad:
    push rbx
    mov rbx, 123
    ret

Al entrar en una función, arriba de la pila está la dirección de retorno. Pero después de push rbx, arriba de la pila queda el valor antiguo de rbx.

Si se ejecuta ret sin hacer antes pop rbx, ret intentará saltar al valor antiguo de rbx como si fuera una dirección de código.

Versión equilibrada:

ft_ok:
    push rbx
    mov rbx, 123
    pop rbx
    ret

pop rbx restaura rbx y también devuelve rsp a la posición correcta, dejando arriba la dirección de retorno real.

8. Funciones hoja

Una función hoja es una función que no llama a otra función.

Ejemplos probables en la parte obligatoria:

ft_strlen
ft_strcpy
ft_strcmp

Si una función no llama a nadie y no necesita registros preservados, puede no tocar la pila.

Una versión compacta de ft_strlen:

global ft_strlen

ft_strlen:
    mov rax, 0

.loop:
    cmp byte [rdi + rax], 0
    je .end
    inc rax
    jmp .loop

.end:
    ret

Aquí:

rdi = dirección inicial de la cadena
rax = índice y contador

La instrucción:

cmp byte [rdi + rax], 0

hace cuatro cosas conceptuales:

1. Calcula la dirección rdi + rax.
2. Lee un byte en esa dirección.
3. Compara ese byte contra 0.
4. Actualiza flags para que je decida si salta.

No compara rdi contra rax. Tampoco modifica rdi ni rax.

9. Alineación de pila

Para funciones hoja simples, normalmente basta con no tocar rsp.

Cuando una función llama a otra, como ocurrirá en ft_strdup al llamar a malloc, hay que pensar en la alineación de la pila antes del call.

Regla práctica por ahora:

Si tu función no llama a nadie, puedes evitar tocar rsp.
Si tu función llama a otra función, debes razonar sobre la pila.

Errores frecuentes
  • Confundir rdi, que contiene una dirección, con [rdi], que lee el contenido de esa dirección.
  • Creer que cmp byte [rdi + rax], 0 compara rdi contra rax; en realidad calcula una dirección, lee un byte y compara ese byte contra cero.
  • Pensar que ret vuelve por magia; realmente usa una dirección de retorno guardada en la pila por call.
  • Modificar rbx, rbp o r12-r15 sin restaurarlos.
  • Hacer push sin el pop correspondiente antes de ret.
  • Usar la pila en funciones simples cuando no hace falta, aumentando el riesgo de romper la ABI.
  • Olvidar que rax es el registro de retorno, aunque su significado concreto dependa de la función.

Objective

Understand the contract that lets a C function call a function written in assembly. By the end you must be able to explain how arguments reach an ASM function, where the return value goes, what ret does, which registers you may freely modify, and why the stack must end up balanced.

1. What the ABI is

ABI stands for Application Binary Interface. It is not a concrete instruction, but an agreement between the calling code and the called code.

In Libasm we use the System V AMD64 ABI on Linux x86-64. Among other things, this ABI defines:

The first argument arrives in rdi.
The second argument arrives in rsi.
The third argument arrives in rdx.
The return value comes out in rax.
ret returns to the caller using an address stored on the stack.
Some registers can be destroyed; others must be preserved.
The stack must be correctly aligned before calling another function.

Without this convention, C and ASM would not know where to leave or look for arguments and results.

2. Function arguments

The first integer or pointer arguments arrive in this order:

1. rdi
2. rsi
3. rdx
4. rcx
5. r8
6. r9

For example:

size_t ft_strlen(const char *s);

ft_strlen receives a single argument, so when ASM is entered:

rdi = address of the first byte of the string

If C calls:

ft_strlen("Hi");

and the string is in memory like this:

AddressContents
0x10000x48 'H'
0x10010x69 'i'
0x10020x00 '\0'

then on entry:

rdi   = 0x1000
[rdi] = 0x48

rdi holds the address. [rdi] reads the contents of that address.

For two arguments:

char *ft_strcpy(char *dst, const char *src);

on entry:

rdi = dst
rsi = src

If dst starts at 0x8000 and src starts at 0x9000:

rdi = 0x8000
rsi = 0x9000

Reading one byte from src and writing it to dst can be done like this:

mov al, [rsi]
mov [rdi], al

3. Return value

The ABI says integer or pointer returns come out in:

rax

If an ASM function ends with:

mov rax, 5
ret

and C did:

int x = mi_funcion();

then C receives:

x = 5

In ft_strlen, rax is used as a counter because at the end that counter is exactly the value the function must return.

In ft_strcpy, the contract requires returning the original dst. That is why you should save that value before advancing the pointer:

mov rax, rdi

You can then modify rdi during the copy while rax keeps the original start of dst.

4. call, ret and the return address

When C calls a function, the CPU conceptually executes a call instruction.

call does two things:

1. Saves on the stack the address to return to.
2. Jumps to the called function.

ret does the opposite:

1. Reads the return address from the stack.
2. Jumps to that address.

That is why an ASM function normally ends with:

ret

The function does not need to manually know which C line to return to. The return address was already saved by call.

5. Volatile and preserved registers

The ABI splits registers into two groups.

Volatile registers, also called caller-saved:

rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11

A function may modify them freely. If the caller needed them kept, the caller had to save them before the call.

Preserved registers, also called callee-saved:

rbx, rbp, r12, r13, r14, r15

If a function modifies one of these, it must restore it before ret.

Incorrect:

mi_funcion:
    mov rbx, 123
    ret

Correct if you really need to use rbx:

mi_funcion:
    push rbx
    mov rbx, 123
    ; use rbx...
    pop rbx
    ret

For the simple mandatory functions, often the best decision is not to use preserved registers at all.

6. The stack

The stack is a memory area managed mainly through rsp, the stack pointer.

On x86-64 the stack grows toward lower addresses.

push rax

is conceptually equivalent to:

rsp = rsp - 8
[rsp] = rax

because a 64-bit register takes 8 bytes.

pop rax

is conceptually equivalent to:

rax = [rsp]
rsp = rsp + 8

Example:

rsp = 0x1000
rax = 55

After:

push rax

you get:

rsp   = 0xff8
[rsp] = 55

7. Stack balance

Every push must be matched by a pop before ret, unless you are adjusting the stack explicitly with sub rsp, ... and add rsp, ....

This function has a serious problem:

ft_bad:
    push rbx
    mov rbx, 123
    ret

When a function is entered, the return address is on top of the stack. But after push rbx, the old value of rbx is on top.

If ret runs without a prior pop rbx, ret will try to jump to the old rbx value as if it were a code address.

Balanced version:

ft_ok:
    push rbx
    mov rbx, 123
    pop rbx
    ret

pop rbx restores rbx and also returns rsp to the correct position, leaving the real return address on top.

8. Leaf functions

A leaf function is a function that does not call another function.

Likely examples in the mandatory part:

ft_strlen
ft_strcpy
ft_strcmp

If a function calls nobody and needs no preserved registers, it can leave the stack untouched.

A compact version of ft_strlen:

global ft_strlen

ft_strlen:
    mov rax, 0

.loop:
    cmp byte [rdi + rax], 0
    je .end
    inc rax
    jmp .loop

.end:
    ret

Here:

rdi = starting address of the string
rax = index and counter

The instruction:

cmp byte [rdi + rax], 0

does four conceptual things:

1. Computes the address rdi + rax.
2. Reads one byte at that address.
3. Compares that byte against 0.
4. Updates flags so je decides whether to jump.

It does not compare rdi against rax. It does not modify rdi or rax either.

9. Stack alignment

For simple leaf functions, usually it is enough to not touch rsp.

When a function calls another, as will happen in ft_strdup calling malloc, you must think about stack alignment before the call.

Practical rule for now:

If your function calls nobody, you can avoid touching rsp.
If your function calls another function, you must reason about the stack.

Common mistakes
  • Confusing rdi, which holds an address, with [rdi], which reads the contents of that address.
  • Thinking cmp byte [rdi + rax], 0 compares rdi against rax; it actually computes an address, reads a byte and compares that byte against zero.
  • Thinking ret returns by magic; it really uses a return address saved on the stack by call.
  • Modifying rbx, rbp or r12-r15 without restoring them.
  • Doing a push without the matching pop before ret.
  • Using the stack in simple functions when it is not needed, raising the risk of breaking the ABI.
  • Forgetting that rax is the return register, even though its concrete meaning depends on the function.
