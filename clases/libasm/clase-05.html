Clase 5 · ft_strlenClass 5 · ft_strlen

rdi · rax · cmp byte [rdi+rax] · xor · invariant · size_t
Objetivo

Construir la primera función real de libasm.a: recorrer memoria byte a byte hasta encontrar el terminador \0, mantener un invariante sobre el contador y devolver la longitud como size_t en rax. Al terminar debes poder explicar por qué el primer argumento llega en rdi, por qué xor rax,rax pone el contador a cero, por qué cmp byte [rdi+rax],0 no necesita movzx, y demostrar con un tester comparativo que ft_strlen empata con strlen en todos los casos definidos.

1. El contrato

size_t ft_strlen(const char *s);
  • s llega en rdi (System V AMD64).
  • Retorno en rax (size_t = 64 bits sin signo).
  • No hay longitud almacenada: hay que buscar el primer 0x00.
  • El terminador no se cuenta. strlen("") == 0, strlen("hola") == 4.
  • strlen(NULL) es indefinido — no lo gestionamos.

Memoria de "hola" si s == 0x1000:

0x1000  0x68 'h'
0x1001  0x6f 'o'
0x1002  0x6c 'l'
0x1003  0x61 'a'
0x1004  0x00 '\0'

2. ABI mínimo que necesitas

rdi = s (solo lo lees)
rax = contador y valor de retorno
flags = resultado de cmp para je/jne

Registros caller-saved (rax, rcx, rdx, rsi, rdi, r8-r11) pueden destruirse. Como no llamas a nadie, no hay que salvar nada ni alinear rsp. xor rax,rax es el idiom para rax=0: 3 bytes frente a 7 de mov rax,0, rompe dependencias y deja ZF=1.

cmp byte [rdi+rax],0 compara directamente el byte en memoria con cero. No necesitas movzx porque no usas el valor, solo los flags. En ft_strcmp sí necesitarás movzx porque restarás byte1 - byte2 y un 0xFF no debe volverse -1.

3. Algoritmo e invariante

size_t ft_strlen(const char *s) {
    size_t i = 0;
    while (s[i] != '\0')
        i++;
    return i;
}

Pasos en ensamblador: rax=0 → leer [rdi+rax] → si es 0 fin → rax++ → repetir → ret.

Invariante: antes de cada iteración, todos los bytes con índice < rax son != 0. Cuando encuentras 0, rax ya es la respuesta y no has contado el terminador.

4. Implementación NASM

default rel
section .text

global ft_strlen
ft_strlen:
    xor     rax, rax          ; i = 0
.loop:
    cmp     byte [rdi + rax], 0
    je      .done
    inc     rax
    jmp     .loop
.done:
    ret

section .note.GNU-stack noalloc noexec nowrite progbits

Desensamblado (objdump -d -M intel):

xor    rax,rax
cmp    BYTE PTR [rdi+rax*1],0x0
je     <done>
inc    rax
jmp    <loop>
ret
  • global exporta T ft_strlen (nm -g).
  • .note.GNU-stack evita pila ejecutable.
  • Función hoja: ningún push/pop.

5. UTF-8 son bytes

strlen cuenta bytes, no caracteres. "café" en UTF-8 son 5 bytes:

'c' 0x63
'a' 0x61
'f' 0x66
'é' 0xc3 0xa9   ; 2 bytes
'\0' 0x00

Por eso strlen("café") == 5, no 4.

Ejercicio 1 · terminador y contador

rdi = 0x1000 con [ 'h' 'o' 'l' 'a' 0 ]. ¿Qué vale rax al terminar? ¿Cuentas el 0?

Mostrar solución

rax=0 'h'→1, 'o'→2, 'l'→3, 'a'→4, 0x00→je .done, ret 4
Ejercicio 2 · cadena vacía

Memoria [ 0x00 ]. ¿Qué devuelve ft_strlen y cuántas iteraciones hace?

Mostrar solución 
Devuelve 0. Comprueba el primer byte, ve 0 y salta a .done sin ningún inc.
Ejercicio 3 · bytes vs caracteres

"café" = 63 61 66 c3 a9 00. ¿Qué devuelve strlen?

Mostrar solución 
5. Cuenta bytes hasta \0. La 'é' son dos bytes (c3 a9), 3+2=5.
Ejercicio 4 · cmp sin movzx

¿Por qué cmp byte [rdi+rax],0 funciona sin movzx y cuándo sí lo necesitarías?

Mostrar solución 
cmp compara el byte en memoria y fija flags. Solo necesitas saber si es cero.
movzx lo necesitas cuando usas el valor (ft_strcmp: byte1 - byte2 sin signo).
Ejercicio 5 · xor vs mov

¿Por qué xor rax,rax es preferible a mov rax,0?

Mostrar solución 
3 bytes (48 31 c0), rompe dependencias y deja ZF=1. mov rax,0 ocupa 7 bytes.
Ejercicio 6 · invariante

Enuncia el invariante y por qué garantiza no contar el \0.

Mostrar solución 
Antes de cada iteración, todo índice < rax es !=0. Solo inc si byte !=0;
cuando encuentra 0 salta sin inc, así que rax = nº de bytes !=0.

Errores frecuentes
  • Contar el terminador (inc antes de cmp).
  • Usar eax de 32 bits y truncar longitudes > 4 GiB.
  • Intentar gestionar NULL (indefinido).
  • Leer de 8 en 8 antes de dominar límites de página.
  • Olvidar global ft_strlen → símbolo U.
  • Añadir push/pop innecesarios en una hoja.

Objective

Build the first real function of libasm.a: walk memory byte by byte until the \0 terminator, keep an invariant on the counter and return the length as size_t in rax. By the end you must be able to explain why the first argument arrives in rdi, why xor rax,rax zeroes the counter, why cmp byte [rdi+rax],0 needs no movzx, and prove with a comparative tester that ft_strlen matches strlen on every defined case.

1. The contract

size_t ft_strlen(const char *s);
  • s arrives in rdi (System V AMD64).
  • Return in rax (size_t = 64-bit unsigned).
  • No stored length: scan for first 0x00.
  • Terminator not counted. strlen("") == 0, strlen("hola") == 4.
  • strlen(NULL) is undefined — we don't handle it.

Memory for "hola" if s == 0x1000:

0x1000  0x68 'h'
0x1001  0x6f 'o'
0x1002  0x6c 'l'
0x1003  0x61 'a'
0x1004  0x00 '\0'

2. Minimal ABI

rdi = s (read-only)
rax = counter and return
flags = cmp result for je/jne

Caller-saved (rax, rcx, rdx, rsi, rdi, r8-r11) may be clobbered. Leaf function: no saves, no rsp alignment. xor rax,rax is the zero idiom: 3 bytes vs 7 for mov rax,0. cmp byte [rdi+rax],0 tests zero directly; you need movzx only when you use the value (e.g. ft_strcmp does byte1 - byte2 unsigned).

3. Algorithm and invariant

size_t ft_strlen(const char *s) {
    size_t i = 0;
    while (s[i] != '\0')
        i++;
    return i;
}

Steps: rax=0 → read [rdi+rax] → if 0 done → rax++ → repeat → ret.

Invariant: before each iteration, every byte with index < rax is != 0. When you hit 0, rax already is the answer.
