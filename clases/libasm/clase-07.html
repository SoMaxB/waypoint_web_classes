Clase 7 · Interfaz de syscallsClass 7 · Syscall interface

syscall · rax 0/1 · rdi rsi rdx · rcx r11 · errno · strace
Objetivo

Entender la frontera usuario/kernel: qué hace syscall, qué registros usa, qué números son read/write y cómo el kernel señaliza errores con retornos negativos que la libc traduce a -1 y errno. Al terminar debes predecir los registros antes de syscall, distinguir una syscall vista en strace de su wrapper C, y explicar por qué read(fd,buf,0)=0 no es error.

1. Función ≠ syscall

C:        ft_write(1, buf, 5)  // rdi=1 rsi=buf rdx=5
ft_write: rax=1               // número de write
          syscall             // → rax = retorno kernel
          // si rax negativo → errno = -rax, rax = -1
          ret

Los 3 primeros args ya están en rdi/rsi/rdx. El 4º de syscall sería r10, no rcx. syscall destruye rcx y r11.

2. Convenciones

Función System VSyscall Linux
Número—rax
Args 1-3rdi rsi rdxrdi rsi rdx
Args 4-6rcx r8 r9r10 r8 r9
Destruidosrax rcx rdx rsi rdi r8-11rcx r11
 
read  = 0
write = 1

3. Qué devuelve el kernel

rax ≥ 0           → éxito: bytes
rax ∈ [-4095,-1]  → error: -errno (ej. -9 = -EBADF)

El rango existe porque nunca hay punteros válidos ahí. Para read/write un éxito no cae en negativo, así que js .error funciona, pero entiende el rango para defensa.

if (ret >= -4095) { errno = -ret; return -1; }

errno es thread-local: __errno_location() → int*, no int errno. Necesitas wrt ..plt (PIE) y preservar el error a través del call.

4. strace

strace -e trace=read,write,openat,close ./demo
write(1, "hola\n", 5) = 5
write(-1, "hola\n", 5) = -1 EBADF (Bad file descriptor)
read(0, "", 0) = 0
openat(AT_FDCWD, "/tmp/...", O_WRONLY|O_CREAT|O_TRUNC, 0644) = 3
write(3, "hola\n", 5) = 5
read(3, "hola\n", 5) = 5

La 2ª línea es rax=-9 decorado. read(...,0)=0 no es error. read parcial (40 de 100) tampoco es error: solo usa buf[0..39], siguiente read dará 0 (EOF).

5. Predicciones y ejercicios

Ejercicio 1 · registros

write(1,"Hi\n",3) con buf=0x6000. ¿rax/rdi/rsi/rdx y qué destruye syscall?

Mostrar solución 
rax=1 rdi=1 rsi=0x6000 rdx=3; destruye rcx r11
Ejercicio 2 · EBADF

write(-1,buf,10) → kernel -9. ¿Retorno y errno?

Mostrar solución 
ret -1, errno 9. rax=-9 → neg → call __errno_location → mov dword [rax],9 → rax=-1
Ejercicio 3 · count 0

read(fd,buf,0) con fd válido.

Mostrar solución 
kernel 0, libc 0, errno intacto. No es error.
Ejercicio 4 · thread-local

¿Por qué no extern int errno?

Mostrar solución 
errno es thread-local/macro. glibc usa __errno_location(). int global rompe hilos y PIE.
Ejercicio 5 · parcial

read(fd,buf,100) sobre archivo de 40 bytes.

Mostrar solución 
40, no error. Siguiente read → 0 (EOF).
Ejercicio 6 · strace

strace dice write(-1,…)=-1 EBADF. ¿Qué había en rax tras syscall?

Mostrar solución 
-9 (0xfffffffffffffff7). El wrapper lo convierte a -1/errno 9.
Errores frecuentes
  • Confundir rax=1 (número) con rdi=1 (fd).
  • Usar rcx para 4º arg (es r10).
  • Creer que syscall preserva rcx/r11.
  • extern int errno en vez de __errno_location.
  • mov [rax],rdi (64b) en vez de mov dword [rax],edi.
  • Olvidar wrt ..plt o no preservar error ante call.
  • Pensar que count=0 o parcial es error.
