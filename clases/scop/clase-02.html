Clase 2 · entorno y primer triánguloClass 2 · environment and first triangle

OpenGL · GLFW · VBO · VAO
Objetivo

Entender qué piezas mínimas hacen falta para abrir una ventana OpenGL y dibujar el primer triángulo. Al terminar esta clase debes poder explicar qué aporta GLFW, qué es un contexto OpenGL, para qué sirven VBO y VAO, cómo se conectan los atributos del shader con los datos del buffer y por qué el bucle de render necesita glfwSwapBuffers() y glfwPollEvents().

Esta clase se basa en la clase 1: ya tenemos el pipeline mental, ahora montamos la infraestructura mínima para dibujar.

1. Qué estamos aislando

Esta clase no carga todavía .obj, no usa matrices MVP y no aplica texturas. Aísla una sola pregunta:

¿Qué tiene que existir antes de que el GPU pueda dibujar algo?

El flujo mínimo es:

programa
  ↓
inicializar librería de ventana
  ↓
crear ventana + contexto OpenGL
  ↓
hacer el contexto actual
  ↓
cargar funciones OpenGL si hace falta
  ↓
crear shaders
  ↓
crear datos del triángulo
  ↓
subirlos a VBO/VAO
  ↓
bucle de eventos
  ↓
dibujar cada frame
  ↓
swap buffers

La ventana no es la escena. Es el destino donde OpenGL presentará el framebuffer final.

2. Qué permite el subject

El subject permite librerías externas para ventana y eventos. Por eso una librería como GLFW puede encargarse de:

  • Crear la ventana.
  • Crear el contexto OpenGL.
  • Gestionar teclado, ratón y cierre de ventana.
  • Mantener el bucle de eventos.

Pero no debe encargarse de las partes que el subject exige implementar o entender personalmente:

  • Parser de .obj.
  • Matrices y transformaciones.
  • Carga/compilación de shaders como caja negra externa.
  • Renderizador completo.

GLFW está permitido porque resuelve infraestructura de ventana/contexto/eventos, no el problema central de Scop.

3. Ventana, contexto y bucle mínimo

Un esqueleto conceptual con GLFW es:

if (!glfwInit())
    fail();

GLFWwindow *window = glfwCreateWindow(800, 600, "scop", NULL, NULL);
if (!window)
    fail();

glfwMakeContextCurrent(window);

while (!glfwWindowShouldClose(window))
{
    render();

    glfwSwapBuffers(window);
    glfwPollEvents();
}

glfwTerminate();

La llamada crítica es:

glfwMakeContextCurrent(window);

OpenGL trabaja sobre un contexto actual asociado al hilo. Sin contexto actual, llamadas como crear buffers, compilar shaders o limpiar la pantalla no tienen un estado OpenGL válido sobre el que operar.

El contexto OpenGL no contiene el .obj parseado. El modelo parseado vive primero en memoria de CPU y después sus datos se suben a buffers del GPU.

4. El primer triángulo

Un triángulo mínimo puede escribirse como posiciones hardcodeadas:

float vertices[] = {
    -0.5f, -0.5f, 0.0f,
     0.5f, -0.5f, 0.0f,
     0.0f,  0.5f, 0.0f,
};

Cada vértice tiene tres float:

x y z

Por tanto:

9 floats / 3 floats por vértice = 3 vértices

Estos datos no aparecen en pantalla por estar en un array C. El GPU no lee automáticamente la RAM de tu programa. Debes subirlos a memoria del GPU.

5. VBO y VAO

Dos objetos aparecen enseguida:

VBO = Vertex Buffer Object
VAO = Vertex Array Object

La forma simple de recordarlos es:

VBO:
  contiene los datos crudos de vértices en memoria del GPU

VAO:
  recuerda cómo interpretar esos datos

Ejemplo conceptual:

VBO:
  -0.5 -0.5 0.0   0.5 -0.5 0.0   0.0 0.5 0.0

VAO:
  location 0 = leer 3 floats por vértice
  stride = 3 floats
  offset = 0

El VBO responde:

¿Dónde están los datos?

El VAO responde:

¿Cómo se leen esos datos?

Código conceptual:

unsigned int vao;
unsigned int vbo;

glGenVertexArrays(1, &vao);
glGenBuffers(1, &vbo);

glBindVertexArray(vao);

glBindBuffer(GL_ARRAY_BUFFER, vbo);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);

glVertexAttribPointer(
    0,                  // location = 0
    3,                  // 3 floats: x, y, z
    GL_FLOAT,
    GL_FALSE,
    3 * sizeof(float),  // stride
    (void *)0           // offset
);
glEnableVertexAttribArray(0);

Más adelante, cuando cada vértice tenga posición, color y UV, el VAO será aún más importante:

x y z   r g b   u v

Entonces necesitaremos describir varios atributos:

location 0: posición, 3 floats, empieza en offset 0
location 1: color,    3 floats, empieza después de posición
location 2: UV,       2 floats, empieza después de color

6. Shaders mínimos

El vertex shader debe tener una entrada compatible con el atributo configurado en el VAO:

#version 330 core

layout (location = 0) in vec3 aPos;

void main()
{
    gl_Position = vec4(aPos, 1.0);
}

La conexión importante es:

VAO dice: location 0 contiene 3 floats por vértice
shader dice: layout(location = 0) in vec3 aPos

Si el VAO configura location = 0 pero el shader espera location = 1, el shader está mirando otra entrada. El resultado puede ser que no se vea nada o que se lean datos incorrectos.

El fragment shader puede devolver un color fijo:

#version 330 core

out vec4 FragColor;

void main()
{
    FragColor = vec4(1.0, 0.5, 0.2, 1.0);
}

Ese vec4 representa:

rojo, verde, azul, alfa

con valores entre 0.0 y 1.0.

7. Compilar y enlazar shaders

El flujo conceptual de shaders es:

código fuente GLSL
  ↓
glCreateShader
  ↓
glShaderSource
  ↓
glCompileShader
  ↓
comprobar errores
  ↓
glCreateProgram
  ↓
glAttachShader(vertex)
  ↓
glAttachShader(fragment)
  ↓
glLinkProgram
  ↓
comprobar errores
  ↓
glUseProgram

El subject no prohíbe escribir funciones propias como load_shader_file() o compile_shader(). Lo que no debes hacer es delegar esa responsabilidad a una librería externa que oculte la carga, compilación, enlazado y reporte de errores.

Para aprender, en esta clase los shaders pueden estar como strings. En el proyecto real convendrá cargarlos desde archivos usando código propio.

8. Dibujar cada frame

Un frame mínimo hace esto:

glClearColor(0.1f, 0.1f, 0.12f, 1.0f);
glClear(GL_COLOR_BUFFER_BIT);

glUseProgram(shader_program);
glBindVertexArray(vao);
glDrawArrays(GL_TRIANGLES, 0, 3);

glfwSwapBuffers(window);
glfwPollEvents();

Responsabilidades:

FunciónResponsabilidad
glClearColorDefine el color con el que se limpiará el fondo.
glClearLimpia el framebuffer actual.
glUseProgramActiva el programa de shaders.
glBindVertexArrayActiva la receta para leer vértices.
glDrawArraysOrdena dibujar vértices secuenciales como triángulos.
glfwSwapBuffersMuestra el frame renderizado.
glfwPollEventsProcesa teclado, ratón, cierre, resize y otros eventos.

Si olvidas glfwPollEvents(), la ventana puede no responder a cierre, teclado o ratón.

9. Doble buffer

Normalmente no dibujas directamente sobre la imagen visible. Se usa doble buffer:

front buffer:
  imagen visible ahora

back buffer:
  imagen que estoy dibujando para el siguiente frame

Cuando terminas de dibujar:

glfwSwapBuffers(window);

el back buffer pasa a verse y el programa empieza a preparar el siguiente frame. Esto evita parpadeos y frames parcialmente dibujados.

10. Qué queda para el Scop real

El triángulo hardcodeado es temporal, pero la infraestructura seguirá existiendo:

Lo que cambiará después es la fuente de los datos:

clase 2:

  vértices parseados desde .obj

Modelo final de conexión:

.obj parseado
  ↓
datos en CPU
  ↓ glBufferData

  ↓ interpretado por
VAO

vertex shader

Ejercicio 1 · contar vértices

Si vertices contiene 9 floats y cada vértice tiene 3 floats, ¿cuántos vértices hay?

Mostrar solución

Hay 3 vértices, porque 9 / 3 = 3.

Ejercicio 2 · location desalineada

Si configuras el VAO con location = 0, pero el vertex shader espera layout(location = 1) in vec3 aPos;, ¿qué problema conceptual hay?

Mostrar solución

El shader está mirando otra entrada distinta. El VAO puso los datos en location 0, pero el shader los pide en location 1.

Ejercicio 3 · poll events olvidado

Si olvidas llamar a glfwPollEvents() dentro del bucle, ¿qué problema práctico esperas?

Mostrar solución

La ventana puede dejar de responder a cierre, teclado, ratón, redimensionado u otros eventos.

Ejercicio 4 · sin doble buffer

Si dibujaras directamente sobre la imagen visible, sin doble buffer, ¿qué efecto visual podría aparecer?

Mostrar solución

Ejercicio 5 · qué sobrevive

En el proyecto final, ¿qué parte de esta clase seguirá existiendo aunque ya no dibujemos un triángulo hardcodeado?

Objective

Understand the minimum pieces needed to open an OpenGL window and draw the first triangle. By the end of this class you must be able to explain what GLFW provides, what an OpenGL context is, what VBO and VAO are for, how the shader attributes connect to the buffer data, and why the render loop needs glfwSwapBuffers() and glfwPollEvents().

This class builds on class 1: we already have the mental pipeline, now we set up the minimum infrastructure to draw.

1. What we are isolating

This class does not load .obj files yet, does not use MVP matrices and does not apply textures. It isolates a single question:

What must exist before the GPU can draw anything?

The minimum flow is:

program
  ↓
initialize window library
  ↓
create window + OpenGL context
  ↓
make the context current
  ↓
load OpenGL functions if needed
  ↓
create shaders
  ↓
create triangle data
  ↓
upload it to VBO/VAO
  ↓
event loop
  ↓
draw each frame
  ↓
swap buffers

The window is not the scene. It is the destination where OpenGL will present the final framebuffer.

2. What the subject allows

The subject allows external libraries for the window and events. That is why a library like GLFW may take care of:

  • Creating the window.
  • Creating the OpenGL context.
  • Handling keyboard, mouse and window close.
  • Running the event loop.

But it must not take care of the parts the subject requires you to implement or understand yourself:

  • The .obj parser.
  • Matrices and transformations.
  • Shader loading/compilation as an external black box.
  • The full renderer.

GLFW is allowed because it solves window/context/event infrastructure, not the core problem of Scop.

3. Window, context and minimal loop

A conceptual skeleton with GLFW is:

if (!glfwInit())
    fail();

GLFWwindow *window = glfwCreateWindow(800, 600, "scop", NULL, NULL);
if (!window)
    fail();

glfwMakeContextCurrent(window);

while (!glfwWindowShouldClose(window))
{
    render();

    glfwSwapBuffers(window);
    glfwPollEvents();
}

glfwTerminate();

The critical call is:

glfwMakeContextCurrent(window);

OpenGL works on a current context associated with the thread. Without a current context, calls like creating buffers, compiling shaders or clearing the screen have no valid OpenGL state to operate on.

The OpenGL context does not contain the parsed .obj. The parsed model first lives in CPU memory and later its data is uploaded to GPU buffers.

4. The first triangle

A minimal triangle can be written as hardcoded positions:

float vertices[] = {
    -0.5f, -0.5f, 0.0f,
     0.5f, -0.5f, 0.0f,
     0.0f,  0.5f, 0.0f,
};

Each vertex has three floats:

x y z

Therefore:

9 floats / 3 floats per vertex = 3 vertices

These data do not show up on screen just because they are in a C array. The GPU does not automatically read your program's RAM. You must upload them to GPU memory.

5. VBO and VAO

Two objects show up right away:

VBO = Vertex Buffer Object
VAO = Vertex Array Object

The simple way to remember them:

VBO:
  holds the raw vertex data in GPU memory

VAO:
  remembers how to interpret that data

Conceptual example:

VBO:
  -0.5 -0.5 0.0   0.5 -0.5 0.0   0.0 0.5 0.0

VAO:
  location 0 = read 3 floats per vertex
  stride = 3 floats
  offset = 0

The VBO answers:

Where is the data?

The VAO answers:

How is that data read?

Conceptual code:

unsigned int vao;
unsigned int vbo;

glGenVertexArrays(1, &vao);
glGenBuffers(1, &vbo);

glBindVertexArray(vao);

glBindBuffer(GL_ARRAY_BUFFER, vbo);
glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);

glVertexAttribPointer(
    0,                  // location = 0
    3,                  // 3 floats: x, y, z
    GL_FLOAT,
    GL_FALSE,
    3 * sizeof(float),  // stride
    (void *)0           // offset
);
glEnableVertexAttribArray(0);

Later, when each vertex has position, color and UV, the VAO becomes even more important:

x y z   r g b   u v

Then we will need to describe several attributes:

location 0: position, 3 floats, starts at offset 0
location 1: color,    3 floats, starts after position
location 2: UV,       2 floats, starts after color

6. Minimal shaders

The vertex shader must have an input compatible with the attribute configured in the VAO:

#version 330 core

layout (location = 0) in vec3 aPos;

void main()
{
    gl_Position = vec4(aPos, 1.0);
}

The important connection is:

VAO says: location 0 holds 3 floats per vertex
shader says: layout(location = 0) in vec3 aPos

If the VAO configures location = 0 but the shader expects location = 1, the shader is looking at another input. The result may be that nothing is visible or that wrong data is read.

The fragment shader can return a fixed color:

#version 330 core

out vec4 FragColor;

void main()
{
    FragColor = vec4(1.0, 0.5, 0.2, 1.0);
}

That vec4 represents:

red, green, blue, alpha

with values between 0.0 and 1.0.

7. Compiling and linking shaders

The conceptual shader flow is:

GLSL source code
  ↓
glCreateShader
  ↓
glShaderSource
  ↓
glCompileShader
  ↓
check errors
  ↓
glCreateProgram
  ↓
glAttachShader(vertex)
  ↓
glAttachShader(fragment)
  ↓
glLinkProgram
  ↓
check errors
  ↓

The subject does not forbid writing your own functions such as load_shader_file() or compile_shader(). What you must not do is delegate that responsibility to an external library that hides loading, compilation, linking and error reporting.

To learn, in this class the shaders can live as strings. In the real project you will want to load them from files using your own code.

8. Drawing each frame

A minimal frame does this:

glClearColor(0.1f, 0.1f, 0.12f, 1.0f);
glClear(GL_COLOR_BUFFER_BIT);

glUseProgram(shader_program);
glBindVertexArray(vao);
glDrawArrays(GL_TRIANGLES, 0, 3);

glfwSwapBuffers(window);
glfwPollEvents();

Responsibilities:

FunctionResponsibility
glClearColorSets the color used to clear the background.
glClearClears the current framebuffer.
glUseProgramActivates the shader program.
glBindVertexArrayActivates the recipe for reading vertices.
glDrawArraysTells the GPU to draw sequential vertices as triangles.
glfwSwapBuffersShows the rendered frame.
glfwPollEventsProcesses keyboard, mouse, close, resize and other events.

If you forget glfwPollEvents(), the window may stop responding to close, keyboard or mouse.

9. Double buffering

Usually you do not draw directly on the visible image. Double buffering is used:

front buffer:
  image visible now

back buffer:
  image I am drawing for the next frame

When you finish drawing:

glfwSwapBuffers(window);

the back buffer becomes visible and the program starts preparing the next frame. This avoids flicker and partially drawn frames.

GLFW: allowed library to create the window, the OpenGL context and handle events.

Common mistakes
  • Thinking that GLFW solves the renderer. It should only solve window, context and events.
  • Believing the OpenGL context holds the .obj model. The model lives in CPU and is later uploaded to buffers.
  • Confusing VBO and VAO: the VBO stores data; the VAO describes how to read it.
  • Setting one location in the VAO and a different one in the shader.
  • Forgetting to check shader compilation and linking errors.
  • Forgetting glfwPollEvents() and getting a window that does not respond.
  • Forgetting glfwSwapBuffers() and not presenting the frame correctly.
  • Believing the hardcoded triangle is part of the final project; it is only a minimal pipeline test.

You have learned that

  • Before drawing you need a window, a current OpenGL context, shaders, buffers and a render loop.
  • GLFW is allowed because it handles window, context and events, not the parser or the renderer math.
  • OpenGL needs a current context before running valid calls.
  • The VBO holds vertex data on the GPU.
  • The VAO remembers how to interpret that data for the shader attributes.
  • layout(location = N) must match the attribute configured in glVertexAttribPointer.
  • The vertex shader works per vertex; the fragment shader decides colors per fragment.
  • glDrawArrays(GL_TRIANGLES, 0, 3) draws three sequential vertices as a triangle.
  • glfwSwapBuffers() presents the finished frame and glfwPollEvents() processes events.
