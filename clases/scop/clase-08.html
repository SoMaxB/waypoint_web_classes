README · make test · audit · defense · mandatory
Objetivo

Cerrar Scop como entrega defendible comprobando cada requisito del subject con una evidencia reproducible y separando claramente la obligatoria del bonus.

1. El README es parte de la entrega

El README.md real documenta descripcion, dependencias, compilacion, ejecucion, controles, estructura, recursos, uso de IA y una tabla de auditoria. La defensa solo puede revisar lo que esta en el repositorio.

2. Auditoria reproducible

cd /home/max/code/42_projects/scop
make fclean
make test
make
        
3. Subject y bonus
La obligatoria esta cubierta por el parser manual, matrices propias, perspectiva, colores por triangulo, PPM, mezcla con mix(), controles, centrado y demo del logo.
El bonus de triangulacion robusta se implemento con ear clipping sobre el eje dominante calculado desde una normal de Newell. Se prueba con tests/concave.obj y las dos teteras.

        
4. Defensa
  1. Por que el orden es P * V * M?
  2. Por que un modelo descentrado orbita?
  3. Como se convierte OBJ base 1 a arrays base 0?
  4. Como llega un PPM al fragment shader?
  5. Por que la transicion usa delta_time?
  6. Que librerias externas estan permitidas?
  7. Que limitacion tiene el fan triangulation?

        
Predicciones y ejercicios
Ejercicio 1 · diagnostico
Si make test pasa pero no aparece la ventana, que investigas?
Mostrar solucion
GLFW, los hints, la creacion del contexto, el display y el cargador manual. El test matematico no prueba el driver.
Ejercicio 2 · bonus
Que evidencia necesitas antes de afirmar que la triangulacion robusta funciona?
Mostrar solucion
Una cara concava, el OBJ original y la version normalizada deben parsearse y arrancar; la prueba debe incluir tests/concave.obj y explicar la proyeccion usada.
Ejercicio 3 · auditoria
Ejecuta todos los comandos del README y marca solo lo observado.
Mostrar solucion
La auditoria termina cuando compilan las pruebas, arrancan tres modelos, funcionan controles y textura, el logo gira centrado y puedes defender las decisiones.

        
Errores frecuentes
  • Confundir compilar con terminar el proyecto.
  • No probar un OBJ distinto del cubo.
  • Ocultar el uso de IA.
  • Reclamar bonus sin una malla concava de prueba.
  • Afirmar que ear clipping resuelve poligonos degenerados sin una politica de error.

        
Has aprendido que
  • Una entrega defendible necesita codigo, comandos y explicacion.
  • El README es un requisito.
  • Una auditoria une cada requisito con una prueba.
  • Las limitaciones conocidas se documentan.
  • El bonus empieza solo despues de la obligatoria.

Predictions and exercises
Exercise 1 · diagnosis
If make test passes but no window appears, what do you inspect?
Show answer
GLFW, context hints, window creation, display and the manual loader. The math test does not test the driver.
Exercise 2 · bonus
What evidence is needed before claiming robust triangulation?
Show answer
A concave face, the original OBJ and the normalized version must start; the test must include tests/concave.obj and explain the projection.
Exercise 3 · audit
Run every README command and mark only what you observed.
Show answer
The audit is complete when builds pass, three models start, controls and texture work, the logo rotates centered and the design decisions are defensible.

        
Common mistakes
  • Confusing compilation with completion.
  • Testing only the cube.
  • Hiding AI usage.
  • Claiming bonus without a concave fixture.
  • Claiming ear clipping handles degenerate polygons without an error policy.
