Clase 4 · matrices MVP y perspectivaClass 4 · MVP matrices and perspective

mat4 · homogeneous coordinates · Model · View · Projection · MVP
Objetivo

Implementar matrices 4x4 propias, coordenadas homogeneas y la composicion Projection * View * Model. Al terminar, el cubo real del proyecto gira sobre su centro y se muestra en perspectiva sin usar GLM.

1. Del OBJ a la pantalla

La clase 3 ya subia posiciones e indices al GPU. Ahora cada posicion atraviesa tres espacios:

posicion local
  -> Model: transforma el objeto
  -> View: expresa el mundo desde la camara
  -> Projection: aplica perspectiva
  -> division por w
  -> rasterizacion

Con vectores columna, la matriz de la derecha actua primero:

clip = Projection * View * Model * vertex

2. Matrices y coordenadas homogeneas

Cada fila de una matriz calcula una coordenada nueva. Usamos w=1 para posiciones y w=0 para direcciones. Asi una traslacion afecta a una posicion pero no a una direccion.

T = [ 1  0  0  tx ]
    [ 0  1  0  ty ]
    [ 0  0  1  tz ]
    [ 0  0  0  1  ]

posicion (x,y,z,1) -> (x+tx,y+ty,z+tz,1)
direccion (x,y,z,0) -> (x,y,z,0)

La implementacion guarda matrices en m[col * 4 + row]. Por eso la traslacion vive en m[12], m[13] y m[14].

t_mat4 mat4_translate(float x, float y, float z)
{
    t_mat4 out = mat4_identity();
    out.m[12] = x;
    out.m[13] = y;
    out.m[14] = z;
    return out;
}

3. Orden de transformacion

Las transformaciones no conmutan. Para que el cubo gire sobre su origen y despues se traslade usamos:

Model = T * R
Model * vertex = T * (R * vertex)

Las funciones mat4_rotate_x, mat4_rotate_y y mat4_rotate_z estan implementadas en src/mat4.c. Si el modelo no estuviera centrado, habria que centrarlo antes de rotar.

4. Camara y perspectiva

Una camara en (0,0,5) se representa moviendo el mundo a z=-5:

view = mat4_translate(0.0f, 0.0f, -5.0f);

La proyeccion usa FOV, proporcion de ventana, near y far. La division posterior por w hace que lo lejano parezca mas pequeno.

projection = mat4_perspective(
    60 grados, 800.0f / 600.0f, 0.1f, 100.0f);
mvp = mat4_mul(projection, mat4_mul(view, model));

5. El MVP llega al shader

uniform mat4 u_mvp;
layout(location = 0) in vec3 aPos;

void main()
{
    gl_Position = u_mvp * vec4(aPos, 1.0);
}

En cada frame, C actualiza el uniform:

glUseProgram(program);
glUniformMatrix4fv(mvp_location, 1, GL_FALSE, mvp.m);

GL_FALSE conserva la matriz column-major. El depth test sigue siendo necesario:

glEnable(GL_DEPTH_TEST);
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);

Errores frecuentes
  • Confundir T * R con R * T.
  • Colocar la traslacion en m[3], m[7], m[11] usando la convencion equivocada.
  • Usar grados directamente en sinf, cosf o tanf.
  • Olvidar subir el uniform despues de activar el programa.
  • Olvidar GL_DEPTH_BUFFER_BIT o el enlace -lm.

Objective

Implement our own 4x4 matrices, homogeneous coordinates and the Projection * View * Model composition. By the end, the real project cube rotates around its center and is displayed in perspective without GLM.

1. From OBJ to the screen

Class 3 already uploaded positions and indices to the GPU. Now each position crosses three spaces:

local position
  -> Model: transforms the object
  -> View: expresses the world from the camera
  -> Projection: applies perspective
  -> division by w
  -> rasterization

With column vectors, the rightmost matrix acts first:

clip = Projection * View * Model * vertex

2. Matrices and homogeneous coordinates

Each matrix row computes one new coordinate. We use w=1 for positions and w=0 for directions, so translation affects positions but not directions. Matrices use m[col * 4 + row]; translation is stored in m[12], m[13] and m[14].

t_mat4 mat4_translate(float x, float y, float z)
{
    t_mat4 out = mat4_identity();
    out.m[12] = x;
    out.m[13] = y;
    out.m[14] = z;
    return out;
}

3. Transformation order

Transformations do not commute. To rotate around the object origin and then translate, use:

Model = T * R
Model * vertex = T * (R * vertex)

The X, Y and Z rotation functions are implemented in src/mat4.c.

4. Camera and perspective

A camera at (0,0,5) is represented by moving the world to z=-5. Perspective uses FOV, aspect ratio, near and far planes; division by w makes distant objects smaller.

view = mat4_translate(0.0f, 0.0f, -5.0f);

Common mistakes
  • Confusing T * R with R * T.
  • Mixing row-major and column-major layouts.
  • Passing degrees directly to trigonometric functions.
  • Forgetting the uniform update or the depth-buffer clear.
  • Forgetting -lm when linking math functions.
