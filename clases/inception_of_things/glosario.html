Glosario

referencia · no memorizar de golpe

Este documento reúne las siglas, herramientas y conceptos que aparecen durante el proyecto. No hace falta memorizarlo de una vez: úsalo como referencia mientras lees el subject, el repo o haces ejercicios.This document collects the acronyms, tools and concepts that come up during the project. You do not need to memorize it all at once: use it as a reference while reading the subject, the repo or doing exercises.

Virtualización e infraestructuraVirtualization and infrastructure

TermSignificado literalLiteral meaningDescripción de usoUsage description
VagrantVagrantHerramienta que declara y levanta máquinas virtuales de forma reproducible a partir de un Vagrantfile. Es la base de p1 y p2.Tool that declares and brings up virtual machines reproducibly from a Vagrantfile. It is the base of p1 and p2.
VagrantfileVagrant FileArchivo que describe las VMs: box, provider, red privada y provisioners. La infraestructura entera de p1 vive en p1/Vagrantfile.File that describes the VMs: box, provider, private network and provisioners. The whole p1 infrastructure lives in p1/Vagrantfile.
boxCaja de VMVM boxImagen base de sistema operativo sobre la que Vagrant clona la VM. Se elige en el Vagrantfile con config.vm.box.Base OS image that Vagrant clones the VM from. It is chosen in the Vagrantfile with config.vm.box.
providerProveedorProviderBackend que ejecuta las VMs (por ejemplo VirtualBox). Define cómo Vagrant crea y apaga las máquinas.Backend that runs the VMs (e.g. VirtualBox). It defines how Vagrant creates and shuts down the machines.
provisionerAprovisionadorProvisionerPaso de configuración que corre dentro de la VM después de crearla: file sube ficheros y shell ejecuta scripts. Sustituyen a las Synced folders.Configuration step that runs inside the VM after creation: file uploads files and shell runs scripts. They replace Synced folders.
red privadaRed privadaPrivate networkSubred 192.168.56.x que solo ven las VMs: 192.168.56.110 para el server y 192.168.56.111 para el worker.Subnet 192.168.56.x visible only to the VMs: 192.168.56.110 for the server and 192.168.56.111 for the worker.
<login>S / <login>SWLogin + Server / ServerWorkerLogin + Server / ServerWorkerHostnames exigidos por el subject: el server y el worker se nombran con tu login de 42.Hostnames required by the subject: the server and worker are named after your 42 login.
Synced foldersCarpetas sincronizadasSynced foldersMecanismo de Vagrant que monta la carpeta del host dentro de la VM (/vagrant). The project disables it: file/shell provisioners upload what is needed.

Kubernetes y K3sKubernetes and K3s

TermSignificado literalLiteral meaningDescripción de usoUsage description
K3sK3sDistribución ligera de Kubernetes, certificada, pensada para edge y VMs. Es lo que se instala en p1 y p2.Lightweight, certified Kubernetes distribution designed for edge and VMs. It is what gets installed in p1 and p2.
K3s serverServidor K3sK3s serverNodo que corre el control-plane y el API server (puerto 6443); aquí también ejecuta cargas. Arranca con el servicio k3s.Node that runs the control-plane and the API server (port 6443); here it also runs workloads. It starts with the k3s service.
K3s agentAgente K3sK3s agentNodo worker puro: se une al cluster con la URL del server y un token. Arranca con el servicio k3s-agent.Pure worker node: it joins the cluster with the server URL and a token. It starts with the k3s-agent service.
nodoNodoNodeUna máquina (física, VM o contenedor) que forma parte del cluster. El subject exige 2 nodos en p1.A machine (physical, VM or container) that is part of the cluster. The subject requires 2 nodes in p1.
workerTrabajadorWorkerNodo que solo ejecuta Pods, sin control-plane. En p1 es <login>SW.Node that only runs Pods, without control-plane. In p1 it is <login>SW.
token de uniónToken de uniónJoin tokenSecreto que permite a un agent unirse al API server. El proyecto lo fija en K3S_TOKEN para que el worker no dependa de copiar node-token.Secret that lets an agent join the API server. The project pins it in K3S_TOKEN so the worker does not rely on copying node-token.
API serverServidor APIAPI serverPunto de entrada de todas las peticiones de Kubernetes. Los clientes se conectan a https://<IP>:6443.Entry point for all Kubernetes requests. Clients connect to https://<IP>:6443.
kubectlKube controlCliente de línea de comandos de Kubernetes: kubectl get nodes, kubectl apply, kubectl describe…Kubernetes command-line client: kubectl get nodes, kubectl apply, kubectl describe…
kubeconfigConfig de kubeKube configFichero con credenciales, cluster y contexto para kubectl; en el server vive en /etc/rancher/k3s/k3s.yaml.File with credentials, cluster and context for kubectl; on the server it lives at /etc/rancher/k3s/k3s.yaml.
namespaceEspacio de nombresNamespacePartición lógica del cluster: default, argocd, dev, gitlab… Aísla recursos y permisos.Logical partition of the cluster: default, argocd, dev, gitlab… It isolates resources and permissions.
PodVainaPodUnidad mínima desplegable: uno o más contenedores que comparten red. Se crea a través de un Deployment.Smallest deployable unit: one or more containers sharing the network. It is created through a Deployment.
DeploymentDespliegueDeploymentRecurso que declara la imagen, las replicas y la estrategia de actualización. Es el "qué quiero" de una app.Resource declaring the image, replicas and update strategy. It is the "what I want" of an app.
ReplicaSetConjunto de réplicasReplica setRecurso intermedio que el Deployment controla para mantener exactamente N Pods vivos.Intermediate resource the Deployment controls to keep exactly N Pods alive.
replicasRéplicasReplicasNúmero de Pods idénticos que mantiene un Deployment. En p2, app2 usa 3 para enseñar balanceo.Number of identical Pods a Deployment keeps. In p2, app2 uses 3 to teach load balancing.
ConfigMapMapa de configuraciónConfig mapRecurso que guarda configuración no sensible (variables de entorno, contenido de páginas). Aquí define qué sirve cada appN.Resource holding non-sensitive configuration (env vars, page content). Here it defines what each appN serves.
labelEtiquetaLabelPar clave/valor pegado a un recurso, ej. app: app2. Agrupa objetos para luego seleccionarlos.Key/value pair attached to a resource, e.g. app: app2. Groups objects so they can be selected later.
selectorSelectorSelectorCriterio label usado por un recurso (Service, Deployment) para elegir a sus Pods. Si no coincide, el Service no encuentra backend.label criterion a resource (Service, Deployment) uses to pick its Pods. If it does not match, the Service finds no backend.
ServiceServicioServiceDirección estable que expone un grupo de Pods y reparte el tráfico entre ellos aunque sus IPs cambien.Stable address that exposes a group of Pods and spreads traffic among them even as their IPs change.
ClusterIPIP de clusterCluster IPTipo de Service con una IP virtual interna, solo visible dentro del cluster. Es el Service estándar, p. ej. el de p2 y los de Argo CD.Service type with an internal virtual IP, visible only inside the cluster. It is the standard Service, e.g. p2's and Argo CD's.
EndpointsPuntos finalesEndpointsLista de IPs de Pods que un Service ha seleccionado. Sin Endpoints, el Service responde 503.List of Pod IPs a Service has selected. Without Endpoints, the Service returns 503.
IngressEntradaIngressRecurso que expone servicios HTTP/HTTPS hacia fuera con reglas de ruta. En p2 es el que decide a qué app va cada petición.Resource exposing HTTP/HTTPS services outward with routing rules. In p2 it decides which app each request goes to.
TraefikTraefikControlador de Ingress que instala K3s por defecto. Recibe el tráfico, lee la regla y enruta.Ingress controller K3s installs by default. It receives traffic, reads the rule and routes.
Host headerCabecera HostHost headerCabecera HTTP con el nombre al que pides (app1.com, app2.com…). El Ingress la usa para elegir backend en p2.HTTP header with the name you are requesting (app1.com, app2.com…). The Ingress uses it to pick the backend in p2.
catch-allAtrapa-todo / defaultCatch-all / defaultRegla del Ingress sin host: recibe cualquier host que no tenga regla propia. En p2 es app3. Un 404 significa que esta regla falta.Ingress rule without a host: it receives any host with no rule of its own. In p2 it is app3. A 404 means this rule is missing.
probeSondaProbeComprobación de salud del kubelet al contenedor: startupProbe tolera arranques lentos, readinessProbe decide cuándo servir tráfico, livenessProbe reinicia.Health check from the kubelet to the container: startupProbe tolerates slow boots, readinessProbe decides when to serve traffic, livenessProbe restarts.
PVC / PVReclamación / volumen persistentePersistent Volume Claim / VolumeEl PVC pide almacenamiento persistente que puede montar un Pod; el PV es el volumen real que lo satisface. GitLab usa 2 PVCs, provisionados por K3d automáticamente.A PVC requests persistent storage a Pod can mount; a PV is the real volume that satisfies it. GitLab uses 2 PVCs, provisioned by K3d automatically.
ReadWriteOnceLectura/escritura únicaRead-write onceModo de acceso de un volumen: un solo pod a la vez puede escribirlo.Volume access mode: only one pod at a time can write it.
RecreateRecrearRecreateEstrategia de Deployment que mata el Pod actual antes de crear el siguiente. Necesaria para un único escritor sobre un PVC.Deployment strategy that kills the current Pod before creating the next one. Needed for a single writer on a PVC.
RollingUpdateActualización por rodajasRolling updateEstrategia por defecto que crea el Pod nuevo primero y elimina el viejo después. Rompería los PVCs de GitLab.Default strategy that creates the new Pod first and removes the old one after. It would break GitLab's PVCs.
rollout statusEstado de despliegueRollout statusComando kubectl rollout status deploy/… que espera a que el Deployment termine de actualizarse. K3s devuelve el control antes de estar listo.Command kubectl rollout status deploy/… that waits for the Deployment to finish updating. K3s returns control before being ready.

Argo CD y GitOpsArgo CD and GitOps

TermSignificado literalLiteral meaningDescripción de usoUsage description
GitOpsGit OperationsFilosofía donde Git es la única fuente de verdad: nadie toca el cluster a mano; una herramienta converge el cluster al estado del repo.Philosophy where Git is the only source of truth: nobody touches the cluster by hand; a tool converges the cluster to the repo state.
Argo CDArgo CDHerramienta GitOps que vigila un repo (repoURL + path) y sincroniza el cluster con su estado. Corre en el namespace argocd.GitOps tool that watches a repo (repoURL + path) and syncs the cluster to its state. It runs in the argocd namespace.
ApplicationAplicaciónApplicationRecurso propio de Argo CD que declara qué repo leer, dónde aplicar y cómo sincronizar. El archivo es confs/application.yaml.Argo CD's own resource declaring which repo to read, where to apply and how to sync. The file is confs/application.yaml.
repoURLRepo URLDe dónde lee Argo CD los manifiestos (GitHub en p3, GitLab interno en el bonus).Where Argo CD reads the manifests from (GitHub in p3, internal GitLab in the bonus).
targetRevisionRevisión objetivoTarget revisionRama, commit o tag a seguir; HEAD = rama por defecto.Branch, commit or tag to follow; HEAD = default branch.
pathRutaPathSubcarpeta del repo donde están los manifiestos, relativa a la raíz del repo.Repo subfolder holding the manifests, relative to the repo root.
destinationDestinoDestinationCluster y namespace donde Argo CD aplica. En p3: el cluster local y dev.Cluster and namespace where Argo CD applies. In p3: the local cluster and dev.
syncPolicyPolítica de syncSync policyCómo y cuándo sincroniza. Con automated, Argo CD sincroniza solo al detectar cambio.How and when it syncs. With automated, Argo CD syncs on its own when it detects a change.
prunePodaPruneBorra del cluster los recursos que ya no existen en Git: "deshace lo que dejas de declarar".Deletes from the cluster resources that no longer exist in Git: "undoes what you stop declaring".
selfHealAutocuraciónSelf-healRevierte cambios hechos a mano en el cluster para volver al estado de Git.Reverts hand-made changes in the cluster to return to Git's state.
SyncedSincronizadoSyncedEstado de la Application: el cluster coincide con el repo.Application status: the cluster matches the repo.
OutOfSyncDesincronizadoOut of syncEstado de la Application: hay intención distinta en el repo aún no aplicada. No es rotura: un sync o el poll (~3 min) la resuelven.Application status: a different intent in the repo not yet applied. Not breakage: a sync or the poll (~3 min) resolves it.
ComparisonErrorError de comparaciónComparison errorArgo CD no puede leer el repo: repoURL mal, path inexistente, rama incorrecta o repo privado sin credenciales. Sí es rotura.Argo CD cannot read the repo: wrong repoURL, missing path, wrong branch or private repo without credentials. This is breakage.
pollingSondeoPollingArgo CD consulta el repo en intervalos para detectar cambios; no es tiempo real ni necesita webhooks.Argo CD checks the repo at intervals to detect changes; not real time and no webhooks needed.
SSA / --server-sideServer-Side ApplyModo de kubectl apply que declara los cambios con el ownership del servidor. Argo CD lo usa porque gestiona recursos propios (CRDs) sin conflicto.kubectl apply mode that declares changes with server ownership. Argo CD uses it because it manages its own resources (CRDs) without conflict.
CRDCustom Resource DefinitionTipo de recurso nuevo que añade un proyecto al cluster. Application es una CRD de Argo CD.New resource type a project adds to the cluster. Application is an Argo CD CRD.

Regla de lecturaReading rule

Cuando aparezca un concepto nuevo, pregúntate: qué pide exactamente el subject sobre esto, qué fichero del repo lo implementa (p1/, p2/, p3/ o bonus/), qué comando lo levanta y qué comando lo verifica, y qué fallo típico le pasa y cómo se diagnostica.When a new concept shows up, ask yourself: what the subject requires about it, which repo file implements it (p1/, p2/, p3/ or bonus/), which command brings it up and which verifies it, and which typical failure it has and how it is diagnosed.

1. ¿Qué pide el subject?        → requisito exacto
2. ¿Qué fichero lo implementa?  → p1/ p2/ p3/ bonus/
3. ¿Qué comando lo verifica?    → kubectl / curl / journalctl
4. ¿Qué fallo típico le pasa?   → y primer comando de diagnóstico

Esta secuencia evita intentar entender todas las siglas de una vez y te prepara para la defensa.This sequence keeps you from trying to understand every acronym at once and prepares you for the defense.
