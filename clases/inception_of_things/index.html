ObjetivoObjective

Aprender el proyecto hasta poder explicarlo y defenderlo como si se hubiera construido desde cero: no solo ejecutar comandos, sino entender qué pide el subject, dónde se cumple en el repo, por qué se implementó así y cómo diagnosticar fallos.Learn the project well enough to explain and defend it as if built from scratch: not just running commands, but understanding what the subject asks, where the repo fulfills it, why it was implemented this way, and how to diagnose failures.

EnfoqueApproach

Cada clase debe cerrar cuatro preguntas:Each class must close four questions:

  • Qué pide exactamente el subject.What the subject asks exactly.
  • Qué ficheros del repo lo implementan.Which repo files implement it.
  • Qué conceptos técnicos hay detrás.Which technical concepts lie behind it.
  • Cómo se demuestra o se diagnostica en una defensa.How it is demonstrated or diagnosed in a defense.

La prioridad es estudiar el proyecto como infraestructura reproducible: Vagrant, K3s, Kubernetes YAML, K3d, Argo CD, GitOps y GitLab local.The priority is to study the project as reproducible infrastructure: Vagrant, K3s, Kubernetes YAML, K3d, Argo CD, GitOps and local GitLab.

02

Vagrant, VM y p1Vagrant, VMs and p1

Cómo se crea un cluster K3s de dos nodos con Vagrant: box, provider, provisioner, red privada, token de unión en el Vagrantfile y flags del server y el worker. Práctica: unir <login>SW a <login>S sin copiar el node-token.How a two-node K3s cluster is created with Vagrant: box, provider, provisioner, private network, the pinned join token in the Vagrantfile, and the server and worker flags. Practice: join <login>SW to <login>S without copying the node-token.
03

Kubernetes básico y p2Basic Kubernetes and p2

Cómo Kubernetes ejecuta tres aplicaciones y las expone con Ingress. Conceptos: ConfigMap, Deployment, ReplicaSet, Pod, labels y selectors, Service ClusterIP, Ingress y Traefik, Host header, replicas y balanceo. Práctica: seguir curl -H "Host: app2.com" http://192.168.56.110 desde el host hasta un Pod.How Kubernetes runs three apps and exposes them with Ingress. Concepts: ConfigMap, Deployment, ReplicaSet, Pod, labels and selectors, ClusterIP Service, Ingress and Traefik, Host header, replicas and load balancing. Practice: trace curl -H "Host: app2.com" http://192.168.56.110 from the host to a Pod.
04

K3d, Argo CD y GitOps con p3K3d, Argo CD and GitOps with p3

Cómo se despliega una aplicación desde GitHub mediante Argo CD. Conceptos: K3s vs K3d, namespaces argocd y dev, Application CRD, repoURL, targetRevision, path, destination, syncPolicy.automated, prune y selfHeal, por qué kubectl apply --server-side es necesario.How an app is deployed from GitHub through Argo CD. Concepts: K3s vs K3d, argocd and dev namespaces, Application CRD, repoURL, targetRevision, path, destination, syncPolicy.automated, prune and selfHeal, why kubectl apply --server-side is required.
05

Bonus: GitLab localBonus: local GitLab

Cómo se cierra el flujo GitOps con un GitLab dentro del cluster. Conceptos: GitLab CE omnibus, PVCs, estrategia Recreate, probes, Service DNS interno, token de API, port-forward, por qué localhost:8081 no sirve como repoURL.How the GitOps flow closes with a GitLab inside the cluster. Concepts: GitLab CE omnibus, PVCs, Recreate strategy, probes, internal DNS Service, API token, port-forward, why localhost:8081 does not work as a repoURL.
